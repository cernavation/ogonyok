# Аудит проекта «Огонёк» — Что есть сейчас

> Честный аудит текущего состояния кодовой базы простыми словами для новичка. Без прикрас: где фейк или заглушка — написано прямо.

---

## Ответы на ключевые вопросы

### 1. Есть ли регистрация с логином и паролем? Где хранятся пользователи?
* **Нет (полноценной серверной регистрации нет).**
  В интерфейсе есть красивая форма входа и регистрации, но она сохраняет аккаунты только локально в памяти вашего браузера (`localStorage` на этом конкретном компьютере), а пароли хэширует через Web Crypto API — на сервер или в базу данных никто не отправляется.

### 2. Данные в облаке или только в браузере (localStorage)?
* **Только в браузере (localStorage).**
  Все ваши записи, гордости, благодарности, настройки и аккаунты лежат в одном ключе `ogonek.v2` в памяти браузера; если очистить кэш или открыть сайт с другого телефона/браузера, данных там не будет.

### 3. Увидит ли друг на своём телефоне мои записи, а я его?
* **Нет, не увидит.**
  Так как сервера и единой базы данных нет, каждый человек открывает изолированную копию сайта только для самого себя и видит зашитый туда демонстрационный дневник и вымышленных друзей.

### 4. Что из этого реально работает, а что заглушки с выдуманными людьми?
* **Почти вся соцсеть — это имитация и заглушки с ботами:**
  * **Сторис:** Заглушка. Личную сторис можно создать только для себя (сохранится в браузере), а все «сторис друзей» — это заранее прописанные в коде карточки выдуманных людей (Михаил Волошин, Мария Соколова и др.).
  * **Чаты:** Заглушка. Красивый интерфейс Telegram, но вы переписываетесь с роботами: скрипт с таймером в 1–2 секунды сам шлёт вам заготовленные ответы и реакции.
  * **Подписки и друзья:** Заглушка. Список друзей и поиск по сообществу берутся из статичных файлов с вымышленными профилями.
  * **Реакции и комментарии:** Локальная симуляция. Вы можете ставить реакции и писать комментарии, но они сохраняются только в вашем браузере, а чужие счётчики захардкожены.
  * **Стрик:** Реально считается кодом, но по старой логике: привязан к календарю и полностью сгорает в 0, если не писать 3 дня подряд.
  * **Аналитика:** Реально считает графики и средние баллы по локальным данным в вашем браузере, но перегружена сложными KPI.
  * **ИИ:** Реально работает (подключён к Google Gemini API через серверный ключ), но промпт намертво зашит под конкретного человека («16-летний Алексей Черн, стартап Memernity, бег босиком»), оценивает только гордости (благодарности не умеет) и не пишет общий итог дня.

### 5. Как сейчас работает логика дней и стрика? Чем отличается от правил 3–5 в PRODUCT_SPEC.md?
* **Сейчас стрик календарный и сгорает при паузе, а не накопительный «счётчик закрытых дней»:**
  * **Сейчас:** Код высчитывает разницу между датами по календарю. Если пропустить больше 3 дней (grace period), стрик **сгорает в 0** (статус `burned`). Новые дни привязываются к календарным суткам.
  * **По ТЗ (правила 3–5):** 
    1. Огонёк **никогда не сбрасывается**: стрик — это просто счётчик успешно закрытых дней дневника. Пропустил месяц — стрик остался прежним.
    2. День привязывается к **следующему незакрытому дню**, а не к календарю (не писал два дня после 20-го — новая запись идёт в 21-й).
    3. День считается закрытым только по выполнению нормы выбранного уровня сложности (1–5 гордостей И благодарностей), и максимум один новый день закрывается за реальные сутки.

### 6. Есть ли SQL-файл для Supabase? Где?
* **Да, есть в двух местах:**
  1. `SUPABASE_FULL_SCHEMA.sql` — в корневой папке проекта (41 КБ).
  2. `supabase/schema.sql` — в папке `supabase/` (41 КБ, точная копия первого файла).
  В них полностью прописана структура таблиц (профили, дни, гордости, благодарности, сторис, чаты, реакции) и RLS-политики, но само приложение к Supabase пока не подключено (в `.env.local` отсутствуют URL и ключи Supabase).

### 7. Какой стек (версии Next, React, UI-библиотеки)? Какие файлы самые большие/тяжёлые и почему приложение медленное?
* **Стек:**
  * **Next.js:** `16.4.0` (экспериментальная предрелизная версия на движке Turbopack).
  * **React / React-DOM:** `19.0.0`.
  * **Стили:** Tailwind CSS `4.3.3` (новый движок v4) + PostCSS.
  * **UI-компоненты и анимации:** `@base-ui/react` (1.5.0), `framer-motion` (14.0.0), `lucide-react` (1.16.0), `clsx`, `tailwind-merge`.
* **Самые тяжёлые файлы:**
  1. `data/migrated/ogonek-import.v1.json` (3.0 МБ) и `data/REAL_RAW_DATA.json` (1.2 МБ) — огромные дампы старых чужих заметок.
  2. `app/globals.css` (282 КБ) — гигантский файл стилей со всеми темами, анимациями и переопределениями.
  3. `lib/ogonek/use-ogonek-store.ts` (118 КБ, 3362 строки!) — монолитное клиентское хранилище на хуках React.
  4. `lib/ogonek/supabase-sync.ts` (82 КБ, 2173 строки) — массивный локальный движок синхронизации.
* **Почему приложение медленное:**
  1. **Монолитный глобальный стейт без селекторов:** Файл `use-ogonek-store.ts` хранит абсолютно всё состояние в одном объекте. Любое мелкое действие (клик на лайк, ввод буквы в поле чата, выбор фильтра) заставляет React перерендеривать гигантское дерево компонентов целиком.
  2. **Огромный объем CSS (282 КБ) и постоянный Fast Refresh:** Тяжёлые стили и частые пересчёты анимаций нагружают процессор браузера.
  3. **Синхронный парсинг `localStorage`:** При каждом изменении весь стейт сериализуется в JSON-строку и сохраняется в синхронный `localStorage`, блокируя главный поток интерфейса.

## 8. Таблица: Что из ТЗ уже есть / частично / нет

| Раздел / Требование ТЗ | Статус | Как сделано сейчас (фактическое состояние) |
| :--- | :---: | :--- |
| **1. Уровни сложности (1–5 гордостей и благодарностей)** | **Нет** | В коде вообще нет понятия уровня сложности. Всегда по умолчанию заложено до 5 записей. |
| **2. Смена уровня не чаще раза в 30 дней с таймером** | **Нет** | Механизм блокировки и таймер «Следующая смена через N дней» отсутствуют. |
| **3. Огонёк никогда не сбрасывается (накопительный стрик)** | **Нет** | Стрик календарный: если пропустить 3 дня подряд, стрик обнуляется (`status: burned`). |
| **4. Запись в первый незакрытый день (независимо от календаря)** | **Нет** | Записи привязываются к календарной дате. Пропуски дней не сдвигают номер дня. |
| **5. Закрытие дня по норме (макс. 1 день за реальные сутки)** | **Нет** | Дневная норма не проверяется, суточного ограничения на закрытие дней нет. |
| **6. Просмотр и редактирование истории за 2+ года** | **Частично** | Историю можно листать в ленте и редактировать (иконка карандаша), но календаря и быстрого перехода к «дню №…» нет. |
| **7. ИИ-оценка гордостей (1–10 + комментарий + итог дня)** | **Частично** | Роут `/api/evaluate` и Gemini API подключены, но промпт жестко зашит под «Алексея Черна и Memernity», а общий итог дня не формируется. |
| **8. ИИ-оценка благодарностей отдельной кнопкой** | **Нет** | Благодарности ИИ вообще не умеет оценивать (нет ни промпта, ни кнопки). |
| **9. Сохранение оценки ИИ без автопересчёта** | **Есть** | Оценки сохраняются в данных дня и не сбрасываются без повторного нажатия. |
| **10. Безопасный серверный вызов Gemini API (ключ на сервере)** | **Есть** | Ключ `GEMINI_API_KEY` хранится в `.env.local` и вызывается только через роут Next.js; есть fallback на эвристику. |
| **11. Публикация одной записи в общую ленту (все/друзья)** | **Частично** | Есть шеринг карточки и сторис, но отдельной сущности «пост в общую ленту из конкретной гордости» нет. |
| **12. Регистрация логин + пароль** | **Частично** | Интерфейс формы готов, но пользователи хранятся только в `localStorage` текущего браузера. |
| **13. Соцсеть: поиск по нику, подписки, лента** | **Частично** | Визуально отрисовано, но работает только с выдуманными демо-аккаунтами локально. |
| **14. Сторис (24 часа)** | **Частично** | Можно создать личную сторис (сохранится в браузере), сторис друзей — статичные вымышленные заглушки. |
| **15. Реакции и комментарии** | **Частично** | Работают локально в браузере, чужие реакции и комментарии — имитация. |
| **16. Чаты в стиле Telegram (группы, папки, пересылка)** | **Частично** | Похожи на Telegram, есть пересылка и карточки, но нет групп, нет папок, а собеседники — автоответчики. |
| **17. Рейтинги (длина дневника, гордости, средний балл, фильтры)** | **Частично** | Есть статичный виджет лидеров в разделе «Поиск», но без фильтров по периодам, без реальных пользователей и без настройки участия. |
| **18. Напоминания в Telegram (ссылка `start=код`, Chat ID, тест)** | **Частично** | Роут отправки сообщения есть, но бота с авторизацией по коду, расписания 1–3 раза в день и проверки незакрытого дня нет. |
| **19. Онбординг (CRM жизни, выбор сложности, тур, первая гордость)** | **Нет** | Онбординга нет: при открытии сайта сразу загружается чужой заполненный дневник на 700+ дней. |
| **20. Аналитика (стрик, графики, лучшая неделя, сравнение месяцев)** | **Частично** | Графики и средние оценки есть, но формата «лучшая неделя / сравнение месяцев / 3 текстовых вывода» нет. |
| **21. Дизайн (один акцентный цвет, мин. 14px, светлая/тёмная темы, моб. панель)** | **Есть** | Тёмная/светлая темы, мобильный навбар и фирменный огонь есть, но стили перетяжелены (282 КБ CSS). |

### Ошибки и предупреждения консоли браузера (включая красную плашку Next.js Issue):
1. **Красная плашка Next.js `1 Issue · 1 Insight` (React Hydration Error):**
   * **Текст ошибки:** `A tree hydrated but some attributes of the server rendered HTML didn't match the client properties: <html lang="ru" - data-theme="x-black" - data-accent="flame" ...>`
   * **Причина:** В файле `app/layout.tsx` на теге `<html>` отсутствует атрибут `suppressHydrationWarning`. При этом инлайн-скрипт `APPEARANCE_BOOTSTRAP_SCRIPT` до старта React проставляет на `<html>` атрибуты темы и акцента из localStorage. React 19 при гидратации видит несовпадение серверного HTML и клиентского DOM и выбрасывает ошибку гидратации, вызывая красную плашку оверлея Next.js.
2. **Предупреждение `[DOM] Password field is not contained in a form`:**
   * **Причина:** Поля ввода паролей или PIN-кодов в некоторых модальных окнах (например, в панели безопасности) отрендерены вне тега `<form>`, о чём браузер Chrome выводит предупреждение для менеджеров паролей.
