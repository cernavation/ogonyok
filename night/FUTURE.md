## 1. Групповые звонки и конференции: LiveKit (Этап 10)

### Текущее состояние (Этап 10)
- Реализованы P2P-звонки «1 на 1» (аудио и видео) с использованием чистого WebRTC, Supabase Realtime broadcast-сигналинга и STUN/TURN (Metered.ca).
- P2P-модель с полносвязной топологией (Full Mesh) идеально подходит для приватных бесед 1-на-1, не требует аренды медиа-серверов и обеспечивает сквозное шифрование между собеседниками с нулевой задержкой.

### Почему Full Mesh неприменим для групповых звонков
- При full-mesh топологии каждый участник звонка должен кодировать и отправлять свой медиапоток каждому собеседнику, а также принимать и декодировать поток от каждого.
- Количество соединений растёт квадратично: для $N$ участников требуется $N \times (N - 1)$ каналов.
- Уже при 4 участниках мобильные устройства перегреваются, исходящий канал забивается (3х битрейт), возникают критические потери пакетов и обрывы соединения.

### Целевое решение: LiveKit SFU (Selective Forwarding Unit)
- **Технология**: **LiveKit** (современный open-source медиа-сервер на Go / Rust с WebRTC SFU архитектурой).
- **Принцип работы**:
  - Каждый участник отправляет **один** медиа-поток на SFU сервер (uplink).
  - LiveKit SFU выборочно пересылает входящие пакеты остальным участникам (downlink) без перекодирования (transcoding), что даёт минимальную задержку (< 100 мс) и низкую нагрузку на CPU.
  - Поддержка симулькаста (Simulcast / Dynacast): сервер автоматически отдаёт уменьшенное разрешение участникам с медленным интернетом или мобильным экраном.
  - Встроенный механизм E2EE (Insertable Streams), модерация комнат, запись звонков и серверные боты (AI-ассистент в звонке).

### Варианты развертывания
1. **LiveKit Cloud**:
   - Быстрый старт без поддержки собственной инфраструктуры.
   - Бесплатный тариф покрывает небольшие сообщества.
   - Переменные окружения: `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`.
2. **Self-Hosted LiveKit Server**:
   - Развертывание через Docker / Kubernetes на собственном VPS (Hetzner / Selectel).
   - Единый контейнер LiveKit + Ingress + Redis для масштабирования.

### План интеграции
1. Создать серверный роут `/api/livekit/token` для генерации JWT-токенов комнат с проверкой прав группы и тарифа.
2. Подключить клиентский SDK `@livekit/components-react` и `livekit-client`.
3. Реализовать компонент `GroupCallRoom` с адаптивной сеткой участников (до 50 человек в видео, до 500 в аудио).
