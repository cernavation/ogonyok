# ПРИНЯТЫЕ РЕШЕНИЯ (DECISIONS)

- **ИИ-оценка**: основной провайдер Gemini (модель из env GEMINI_MODEL), при ошибке или лимите автоматический фолбэк на DeepSeek. Один серверный модуль lib/server/ai.ts, UI не знает о провайдере и не пишет «Gemini» в тостах, пишет «ИИ».
- **Каноническая модель дневника**: `days` + `prides` + `gratitudes`. Для совместимости создать VIEW `diary_days`. Таблицы `entries` и вся «схема V2» признаются устаревшими.
- **Приглашение /invite/[username]**: сначала брендированная карточка пригласившего (аватар, стрик, «Присоединиться»), затем регистрация, затем автоматическая заявка в соратники.
- **RLS включён везде**, allow_all_dev удалён навсегда. Демо-режим без входа работает только на localStorage.
- **Звонки**: оставить текущий WebRTC + Supabase Realtime signaling, добавить TURN через Metered.ca (ключи в env, выдача через /api/webrtc/ice-servers с проверкой авторизации).
- **Тарифы**: free | pro | ultra. Значение `premium` в базе мигрируется в `pro`. Тариф меняется ТОЛЬКО ролью service_role (админ-скрипт, SQL Editor, вебхук оплаты). Клиент, даже авторизованный, изменить тариф не может.
- **Rate-limit и квоты** хранятся в Postgres (RPC), а не в памяти лямбды.
- **Терминология в UI**: «Соратники» везде (убрать смесь «Друзья/Круг соратников/Подписки», где это один и тот же смысл). «Подписки» остаются отдельной односторонней концепцией.
- **Хранилище медиа чатов (Этап 8)**: приватный бакет `chat-media` (`public = false`) с контролем RLS и подписанными URL (Signed URLs) на 1 час с кэшированием в клиенте. Публичный бакет запрещён, чтобы исключить утечки ссылок на персональные фото, голосовые и документы.
- **Редактирование сообщений (Этап 8)**: без ограничения по времени для автора сообщения, с фиксацией `is_edited = true` и `edited_at = now()`. Удаление для всех разрешено автору или владельцу/администратору группы.
- **Архитектура чатов (Этап 8)**: каноническая модель реляционных тредов `threads` (direct и group) и участников `thread_members`. Прямые сообщения привязаны через `direct_messages.thread_id` с обратной совместимостью через автомиграцию существующих `thread_key`.
- **Индивидуальная аудитория записей (Этап 9)**: каждая гордость и благодарность имеет собственную независимую видимость `'private' | 'friends' | 'public' | 'groups'`. Для `'groups'` конкретные группы хранятся в реляционной таблице `entry_audiences(entry_kind, entry_id, group_id)`.
- **Интеграция групп и мессенджера (Этап 9)**: при создании группы в `groups` автоматически создаётся связанный тред в `threads` (`kind = 'group'`), участники группы автоматически синхронизируются в `thread_members`.
- **Инвайт-ссылки групп (Этап 9)**: ссылка `/g/[code]` имеет ограниченный срок действия (7 дней), проверяет квоту тарифа владельца группы на максимальное число участников (`maxGroupMembers`), а прямое приглашение возможно только из взаимных соратников.
- **Терминология и локализация интерфейса (Этап 15)**: Полное устранение англицизмов в русскоязычном интерфейсе. «Evidence Vault» канонически переведён как «Сейф доказательств» во всех компонентах, карточках, табах и системных сообщениях. Единый термин для взаимных связей — «Соратники». Единая шкала токенов: радиусы 4/8/12/16/24/9999px, отступы 4/8/12/16/24/32px, микро-анимации 150-250мс ease, сенсорные зоны на мобильных строго >= 40×40px.
- **Архитектура селекторов стора (Этап 16)**: `lib/ogonek/perf-storage.ts` содержит чистую функцию `shallowEqual`. Для реактивных подписок используется канонический `useSyncExternalStoreWithSelector`. Горячие компоненты (лента, сайдбар, композер, мессенджер) переведены на срезы `useFeedSlice`, `useSidebarSlice`, `useComposerSlice`, `useChatSlice`, а также стабильный хук действий `useOgonekActions()`. Обновление сообщений в `chatThreads` изолировано и не приводит к ре-рендеру ленты (0 лишних рендеров).
- **Надёжность и очистка хранилища (Этап 16)**: Запись в `localStorage` дебаунсится на 300 мс (`scheduleDebouncedSave`), с гарантированным сбросом через `flushSaveStore()` при `beforeunload`. Функция `sanitizeStateForStorage` вычищает любые Base64 строки (> 2 КБ или `data:image`) из `localStorage` (фото дня — только ссылки Storage и ID IndexedDB). При `QuotaExceededError` применяется 3-этапная мягкая деградация (сброс черновика → усечение кэша до 30 дней → очистка истории чатов) без краша приложения.
- **Оффлайн-очередь (Этап 16)**: При отсутствии сети (`!navigator.onLine`) создаваемые дни помечаются `isOfflinePending = true`, оптимистично отображаются в ленте с бейджем «Сохранено локально, отправится при появлении сети» и помещаются в очередь `ogonek.offline_sync_queue`. При возвращении сети (`online` event) записи автоматически выгружаются в Supabase через `processOfflineQueue`.
- **Защита от CLS (Этап 16)**: Все фото в `DayCard` зафиксированы в контейнере `aspect-[16/9]` с Next.js `<Image>`, `sizes` и data-URL SVG shimmer плейсхолдером (`generateShimmerBlurDataUrl`), аватары имеют явные `width={40}` и `height={40}`, а состояния загрузки ленты отображают `<DayCardSkeleton />`, что обеспечивает CLS = 0.0000 (норма < 0.1).
