# ПРОТОКОЛ НОЧНОЙ СМЕНЫ

А. ПРАВИЛО ДОКАЗАТЕЛЬСТВ. Фраза «готово» без доказательства запрещена. У каждого пункта задачи три возможных статуса: DONE, PARTIAL, NOT DONE. DONE ставится только если лежит доказательство в night/evidence/<номер этапа>/:
   - вывод команд (tsc, lint, build, тесты) в .txt;
   - скриншоты Playwright (десктоп 1440x900 и мобильный 390x844) для любого UI-изменения;
   - для БД: результаты SQL-запросов от имени двух тестовых пользователей (что разрешено и что запрещено);
   - для API: curl/fetch-вывод с кодами ответов.
Б. ОТЧЁТ ЭТАПА: night/reports/STAGE_XX.md, таблица: требование | статус | файл-доказательство | заметки. Запрещены слова «должно работать», «скорее всего», «предположительно». Нет доказательства значит PARTIAL или NOT DONE.
В. САМОПРОВЕРКА «ПРОТИВ ВРАНЬЯ». Перед закрытием этапа: открой каждый DONE-пункт, открой его доказательство, сверь с требованием глазами. Что не подтверждается, понизь до PARTIAL и допиши в отчёт раздел «Где я мог ошибиться». Добавь раздел «Чего я НЕ проверял».
Г. ВОРОТА КАЧЕСТВА перед каждым коммитом: `npx tsc --noEmit` = 0 ошибок, `npm run lint` без новых ошибок, `npm run build` exit 0, `npm run verify:all` (если есть). Запрещено: возвращать `ignoreBuildErrors`, ослаблять или удалять существующие тесты, мокать, чтобы тест прошёл, оставлять пустые обработчики, `console.log` в onClick, TODO в рабочем коде.
Д. КАЖДАЯ КНОПКА, которую ты создаёшь или трогаешь, имеет обработчик, состояния loading/disabled/error, фокус с клавиатуры, aria-label. Бесполезную кнопку удаляй.
Е. БЕЗОПАСНОСТЬ: секреты не печатать и не коммитить; работать только со staging-базой (.env.staging.local); боевую базу не трогать. Любой SQL пиши в supabase/migrations/NNN_name.sql (идемпотентный, повторный запуск безопасен), а порядок применения веди в night/SQL_ORDER.md.
Ж. БЛОКЕРЫ: если упёрся, запиши в night/BLOCKERS.md (что, почему, что нужно от человека) и переходи к следующей независимой задаче. Не останавливайся и не задавай вопросов: решения уже приняты в DECISIONS.md.
З. ПРОГРЕСС: после каждого этапа обновляй night/PROGRESS.md (что сделано, что дальше, текущая ветка и коммит). При нехватке контекста сохрани прогресс и продолжи с этого места.
И. НИЧЕГО НЕ ДОДУМЫВАТЬ: перед правкой файла прочитай его и связанные вызовы. Перед удалением кода найди все его использования (grep).
