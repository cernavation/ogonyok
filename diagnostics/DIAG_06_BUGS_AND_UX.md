# ДИАГНОСТИЧЕСКИЙ ОТЧЁТ: РЕЕСТР БАГОВ И UX-ДЕФЕКТОВ (BUGS & UX)
> **Файл:** `diagnostics/DIAG_06_BUGS_AND_UX.md`  
> **Дата аудита:** 9 ноября 2026 г.  
> **Роль:** Старший Full-Stack инженер и аудитор  
> **Статус:** ТОЛЬКО ДИАГНОСТИКА (код не изменялся, миграции не применялись)

---

## 1. Классификация приоритетов багов

- **P0 (Блокирующий / Critical / Data Breach)**: Утечки данных, уязвимости доступа, падение ключевых бизнес-процессов, расхождение схем данных.
- **P1 (Высокий / Major)**: Неработающие ключевые функции (звонки за NAT, ссылка-приглашение 404, Base64-раздувание БД, сбои Storage).
- **P2 (Средний / Moderate)**: Мёртвые кнопки, расхождения клиентов, XSS-векторы, отсутствие интеграции оплаты.
- **P3 (Низкий / UI & Accessibility)**: Утечки оранжевого цвета (B4), контрастность тем, доступность клавиатуры, неоптимизированные изображения.

---

## 2. Полный реестр багов (P0 — P3)

### 2.1. Приоритет P0: Критические дефекты и утечки

#### БАГ-P0-01: Тотальное отключение RLS в базе данных (Critical Security Hole)
- **Файл:Строка:** `SUPABASE_2.0_MIGRATION.sql:424-445`, `supabase/disable_days_rls.sql:6-8`.
- **Воспроизведение:**
  1. Открыть браузерную консоль на любой странице приложения.
  2. Выполнить:
     ```js
     const client = window.__supabase || (await import('@/lib/supabase/client')).getSupabase()
     const { data } = await client.from('direct_messages').select('*')
     console.log('Чужие сообщения:', data)
     ```
  3. Запрос успешно возвращает **полный массив сообщений всех пользователей** без авторизации.
- **Причина:** Разработчики отключили RLS (`ALTER TABLE ... DISABLE ROW LEVEL SECURITY`) или создали тотальные политики `allow_all_dev` (`FOR ALL USING (true) WITH CHECK (true)`), чтобы обойти сложности отладки офлайн-синхронизации.

#### БАГ-P0-02: Telegram-крон проверяет `diary_days`, а приложение пишет в `days`
- **Файл:Строка:** `app/api/telegram/cron/route.ts:61-66` vs `lib/ogonek/use-ogonek-store.ts:654`.
- **Воспроизведение:**
  1. Пользователь заходит в приложение, заполняет дневник и закрывает день. Запись успешно сохраняется в `days` и `prides`.
  2. В назначенное время срабатывает Vercel Cron по адресу `/api/telegram/cron`.
  3. Сервер делает запрос:
     ```ts
     const { data: todayDays } = await supabase.from('diary_days').select('*').eq('user_id', u.id)...
     ```
  4. Таблица `diary_days` пуста (день сохранён в `days`).
  5. Бот отправляет пользователю ложное напоминание: *«Огонёк ждёт тебя! Твой день дневника ещё не закрыт»*, несмотря на то, что день был закрыт.
- **Причина:** Архитектурный рассинхрон между схемой 1.0 (`days`) и схемой V2 (`diary_days`).

#### БАГ-P0-03: Запланированные сообщения чата попадают в `messages`, а читаются из `direct_messages`
- **Файл:Строка:** `app/api/cron/deliver-scheduled/route.ts:57` vs `components/ogonek/messenger/messenger-chat-pane.tsx:286`.
- **Воспроизведение:**
  1. В чате запланировать отправку сообщения через модалку `ChatScheduleModal`. Запись появляется в `scheduled_messages`.
  2. Срабатывает крон `/api/cron/deliver-scheduled`.
  3. Крон переносит запись в таблицу `public.messages`:
     ```ts
     await supabase.from('messages').insert({ ... })
     ```
  4. Пользователь открывает чат. Чат слушает и читает таблицу `public.direct_messages`.
  5. Доставленное сообщение **никогда не отобразится** в переписке.
- **Причина:** Крон написан под схему `supabase/schema.sql`, а UI мессенджера — под `SUPABASE_2.0_MIGRATION.sql`.

#### БАГ-P0-04: Серверный роут `/api/evaluate` требует `DEEPSEEK_API_KEY`, а UI объявляет Gemini
- **Файл:Строка:** `app/api/evaluate/route.ts:15-25` vs `components/ogonek/composer.tsx:484, 540`.
- **Воспроизведение:**
  1. В `.env.local` или Vercel задан `GEMINI_API_KEY` (как указано в `.env.example`). Переменная `DEEPSEEK_API_KEY` отсутствует.
  2. В Композере пользователь нажимает кнопку ИИ-оценки ⚡.
  3. Появляется Toast: *«⚡ Gemini анализирует масштаб побед...»*.
  4. Сервер возвращает 500: `Ключ DEEPSEEK_API_KEY не задан в переменных окружения`.
  5. UI перехватывает ошибку и выводит: *«Ключ GEMINI_API_KEY не задан в Environment Variables»*.
- **Причина:** Коммит `8e7ba9c` перевёл оценку на DeepSeek API (`https://api.deepseek.com/chat/completions`), но не обновил формулировки и обработку ошибок в клиентском компоненте `composer.tsx`.

### 2.2. Приоритет P1: Высокий (Major Bugs)

#### БАГ-P1-01: Ссылка-приглашение друга отдаёт 404 Not Found
- **Файл:Строка:** `components/ogonek/friends-manager.tsx:256` и `lib/ogonek/profile-share.ts:187-194`.
- **Воспроизведение:**
  1. В менеджере соратников нажать кнопку «Пригласить».
  2. Скопировать ссылку вида `https://ogonek.app/invite/cernavation`.
  3. Открыть ссылку в новой вкладке.
  4. Отображается страница ошибки: **404 · Страница не найдена**.
- **Причина:** В каталоге `app/` отсутствует роут `invite/` (нет `app/invite/[username]/page.tsx`).

#### БАГ-P1-02: Сбои WebRTC-звонков за симметричным NAT (отсутствие TURN-сервера)
- **Файл:Строка:** `components/ogonek/messenger/chat-call-modal.tsx:205-209`.
- **Воспроизведение:**
  1. Начать звонок между смартфонами в мобильных сетях (LTE/5G) разных сотовых операторов (например, МТС и Теле2) либо в корпоративном Wi-Fi.
  2. Нажать «Принять».
  3. Статус вызова зависает на `Инициализация...` или `Подключение медиа...`.
  4. Голос и видео не передаются. Через 15 секунд соединение переходит в статус `failed` / `Переподключение...`.
- **Причина:** В `RTCPeerConnection` прописаны только серверы Google STUN. При Symmetric NAT / CGNAT прямое P2P-соединение невозможно без ретранслятора TURN (Traversal Using Relays around NAT).

#### БАГ-P1-03: Раздувание базы данных через Base64 DataURL в сообщениях чата
- **Файл:Строка:** `components/ogonek/messenger/chat-voice-recorder.tsx:226`, `components/ogonek/messenger/chat-composer.tsx:169`.
- **Воспроизведение:**
  1. Записать 60-секундное голосовое сообщение или отправить фотографию в чат.
  2. Открыть запись в базе данных Supabase в таблице `direct_messages`.
  3. Поле `media` содержит строку Base64 размером 2–5 МБ.
  4. При открытии диалога клиент загружает десятки мегабайт текста.
- **Причина:** Файлы не загружаются в бакет Storage (`storage.from('...').upload`), а вшиваются непосредственно в JSONB-структуру строки таблицы.

#### БАГ-P1-04: Ошибка «Bucket not found» при загрузке фото через `lib/supabase/client.ts`
- **Файл:Строка:** `lib/supabase/client.ts:222` vs `supabase/migrations/001_ogonyok_media_storage.sql:9`.
- **Воспроизведение:**
  1. Вызвать функцию `uploadPhoto` из `lib/supabase/client.ts`.
  2. Запрос падает с ошибкой Supabase: `Bucket not found`.
- **Причина:** В `client.ts:222` захардкожено имя бакета `ogonek-media` (через "e"), а миграция SQL создаёт бакет `ogonyok-media` (через "yo").

#### БАГ-P1-05: Падение SQL CHECK Constraint при добавлении в друзья
- **Файл:Строка:** `lib/supabase/api.ts:453` vs `SUPABASE_FULL_SCHEMA.sql:454`.
- **Воспроизведение:**
  1. В окружении с накатанной схемой `SUPABASE_FULL_SCHEMA.sql` нажать «Подписаться» у пользователя.
  2. Запрос завершается с ошибкой Postgres:
     `new row for relation "friendships" violates check constraint "friendships_status_check"`.
- **Причина:** Ограничение SQL разрешает статусы `friend`, `following`, `incoming-request`, `outgoing-request`, `dismissed`. Код отправляет литерал `'accepted'`.

#### БАГ-P1-06: Локальный поиск по друзьям не находит реальных пользователей базы
- **Файл:Строка:** `components/ogonek/friends-manager.tsx:45-53, 188`.
- **Воспроизведение:**
  1. Открыть «Круг соратников».
  2. Ввести в поиск юзернейм зарегистрированного пользователя, не входящего в топ-40 недавних профилей.
  3. Поиск выдаёт заглушку «Никого не найдено».
- **Причина:** Функция `matches()` фильтрует только локальный массив `dbUsers` (40 записей), не отправляя запрос `searchProfiles` на сервер.

### 2.3. Приоритет P2: Средний (Moderate Issues)

#### БАГ-P2-01: Мёртвая кнопка «Настройки ленты» в шапке HomeView
- **Файл:Строка:** `components/ogonek/views/home-view.tsx:210-217`.
- **Воспроизведение:**
  1. На Главной странице нажать на иконку трёх точек (`MoreHorizontal`) рядом с заголовком «Главная».
  2. Никакого визуального отклика, меню не открывается.
- **Причина:** Тег `<button>` не содержит атрибута `onClick`. Готовый компонент `FeedSettingsMenu` не импортирован.

#### БАГ-P2-02: Stored XSS уязвимость в превью ссылок мессенджера
- **Файл:Строка:** `components/ogonek/messenger/chat-message-bubble.tsx:703`.
- **Воспроизведение:**
  1. Отправить в чат сообщение с полезной нагрузкой:
     `linkPreview: { url: "javascript:alert(document.domain)", siteName: "Attack" }`.
  2. Получатель кликает по карточке превью ссылки.
  3. В браузере выполняется произвольный JavaScript-код.
- **Причина:** Значение `href={message.linkPreview.url}` рендерится без проверки протокола (`http://`, `https://`).

#### БАГ-P2-03: Дублирование экземпляров браузерного клиента Supabase
- **Файл:Строка:** `lib/supabase/client.ts` и `lib/ogonek/supabase-client.ts`.
- **Воспроизведение:**
  1. Открыть страницу со списком диалогов и перепиской.
  2. В DevTools Network наблюдать два независимых WebSocket-соединения к `realtime/v1/websocket`.
- **Причина:** Компоненты приложения хаотично импортируют `getSupabase` из двух разных файлов, создавая два параллельных синглтона.

#### БАГ-P2-04: Маскировка отсутствия сервисного ключа `SUPABASE_SERVICE_ROLE_KEY`
- **Файл:Строка:** `lib/supabase/server.ts:4`.
- **Воспроизведение:**
  1. Запустить сервер без `SUPABASE_SERVICE_ROLE_KEY`.
  2. Серверный клиент инициализируется с `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
  3. Серверные API падают с невнятными ошибками RLS вместо явного сообщения о пропущенной переменной.
- **Причина:** Конструкция `SUPABASE_SERVICE_ROLE_KEY = process.env.SUPABASE_SERVICE_ROLE_KEY || process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY`.

#### БАГ-P2-05: Заглушка биллинга на странице «Премиум»
- **Файл:Строка:** `components/ogonek/views/premium-view.tsx:83-89`.
- **Воспроизведение:**
  1. Перейти на вкладку «Премиум».
  2. Нажать «Оформить Премиум за 490 ₽/мес».
  3. Открывается модалка, предлагающая вручную написать в Telegram пользователю `@cernavation`.
- **Причина:** Отсутствует интеграция платежного шлюза (Stripe, CloudPayments, ЮKassa).

### 2.4. Приоритет P3: Дизайн, Акценты (B4), Контраст и Доступность

#### БАГ-P3-01: Утечка зашитого оранжевого цвета `#FF5C00` (Баг B4)
- **Файлы:Строки:**
  - `components/ogonek/bottom-nav.tsx:87`: индикатор бейджа `bg-[#ff5c00]`.
  - `components/ogonek/landing/guest-landing.tsx:151, 166, 227, 238`: свыше 25 элементов с жестко зашитым `#FF5C00`.
  - `components/ogonek/onboarding-modal.tsx:348, 398, 457`: маркеры тура и границы `border-[#FF5C00]`.
  - `components/ogonek/ui/empty-state.tsx:25`: фон иконки `bg-[#FF5C00]/10`.
  - `app/privacy/page.tsx:23, 38, 49` и `app/terms/page.tsx:11, 23`: зашитые оранжевые маркеры.
  - `app/globals.css:9998-10022`: костыльные CSS-селекторы вида `html[data-accent] .text-\[\#FF5C00\] { color: var(--accent) !important; }`.
- **Воспроизведение:**
  1. В Настройках выбрать тему `apple-light` и акцент «Небесный» (Blue `#1D9BF0`).
  2. В нижнем меню бейдж уведомлений остаётся оранжевым.
  3. В гостевом лендинге и модалке онбординга кнопки остаются ярко-оранжевыми.
- **Причина:** Использование Tailwind-классов произвольных значений (`bg-[#FF5C00]`) вместо семантических токенов `var(--accent)`.

#### БАГ-P3-02: Отключена оптимизация изображений Next.js (`unoptimized: true`)
- **Файл:Строка:** `next.config.mjs:7`.
- **Воспроизведение:**
  1. Загрузить обложку профиля размером 4 МБ.
  2. Браузер скачивает исходный файл целиком без сжатия в WebP/AVIF и без генерации `srcset`.
- **Причина:** Флаг `images: { unoptimized: true }` полностью отключает встроенный оптимизатор Next.js Image.

#### БАГ-P3-03: Подавление ошибок типов при сборке
- **Файл:Строка:** `next.config.mjs:4`.
- **Воспроизведение:** Наличие `typescript: { ignoreBuildErrors: true }` маскирует ошибки несовместимости типов в продакшен-бандле.

#### БАГ-P3-04: Недостаточный контраст вторичного текста в светлой теме (WCAG AA)
- **Файл:Строка:** `styles/tokens.css:48-60`.
- **Воспроизведение:**
  1. Включить тему `apple-light`.
  2. Цвет вторичного текста `--text-2` равен `#536471` на подложке `#F7F9F9`.
  3. Коэффициент контрастности составляет ~3.8:1, что ниже стандарта WCAG 2.1 AA (минимум 4.5:1 для обычного текста).

#### БАГ-P3-05: Отсутствие доступности с клавиатуры (A11y) в карточке дня
- **Файл:Строка:** `components/ogonek/day-card.tsx:75-90`.
- **Воспроизведение:**
  1. Навигация по ленте с помощью клавиши `Tab`.
  2. Контекстное меню кнопки «...» не имеет атрибутов `aria-haspopup="menu"` и `aria-expanded="false"`. Скринридер не сообщает незрячему пользователю о наличии выпадающего списка действий.
