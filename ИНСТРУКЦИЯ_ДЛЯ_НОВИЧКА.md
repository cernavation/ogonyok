## Шаг A. Создание бесплатного проекта на Supabase

1. Открой в браузере сайт: [https://supabase.com](https://supabase.com)
2. Нажми зелёную кнопку **«Start your project»** (или **«Sign in»** через GitHub / Google).
3. В панели управления нажми кнопку **«+ New Project»** (Новый проект).
4. Заполни 3 поля:
   * **Name (Имя проекта):** введи `Ogonek`
   * **Database Password (Пароль базы данных):** нажми кнопку **«Generate a password»** (Сгенерировать) и **обязательно скопируй его в блокнот**.
   * **Region (Регион):** выбери `Frankfurt (EU)` или ближайший к тебе регион.
5. Нажми зелёную кнопку **«Create new project»**.
6. Подожди 1–2 минуты, пока база инициализируется (появится зелёная надпись *«Project is ready»*).

## Шаг B. Накатывание базы данных через SQL Editor

1. В левом меню Supabase нажми на иконку **SQL Editor** (иконка терминала `>_`).
2. Нажми зелёную кнопку **«+ New query»** (или Create new snippet).
3. В проекте на твоём компьютере открой файл `supabase/schema.sql`.
4. Выдели весь текст внутри файла (Ctrl+A на Windows/Linux или Cmd+A на Mac) и скопируй (Ctrl+C / Cmd+C).
5. Вставь скопированный SQL-код в большое поле SQL Editor в Supabase.
6. В правом нижнем углу нажми кнопку **«Run»** (или комбинацию клавиш `Cmd + Enter` / `Ctrl + Enter`).
7. Через пару секунд внизу появится зелёное сообщение: **«Success. No rows returned»**.
   * *Все таблицы (профили, дни, гордости, благодарности, чаты, сторис, стрик) созданы и защищены!*

## Шаг C. Копирование ключей в файл .env.local

1. В левом меню панели Supabase нажми в самом низу на значок шестерёнки **«Project Settings»** (Настройки проекта).
2. В появившемся подменю нажми на раздел **«API»**.
3. Ты увидишь блок **Project API keys** и **Project URL**:
   * **Project URL:** скопируй значение (выглядит как `https://abcdefghijkl.supabase.co`).
   * **anon / public key:** скопируй длинный ключ, начинающийся с `eyJhbGciOi...`
   * **service_role key:** нажми кнопку *Reveal* (показать) рядом с `service_role secret` и скопируй его.
4. В корне папки проекта на компьютере открой файл `.env.local` (если его нет, создай копию файла `.env.example` и переименуй в `.env.local`).
5. Вставь ключи:
   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://твой-проект.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...твой_anon_key
   SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...твой_service_role_key
   ```
6. Сохрани файл.

## Шаг C2. Хранилище Supabase Storage и опциональные ключи

1. **Бакеты Storage (создаются автоматически скриптом `supabase/schema.sql`):**
   * `covers` (публичный) — обложки профилей с кадрированием 3:1.
   * `avatars` (публичный) — аватары пользователей с кадрированием 1:1.
   * `chat-media` (приватный) — фото, видео, голосовые и документы в мессенджере.
2. **Опциональные переменные в `.env.local`:**
   * `GIPHY_API_KEY` — бесплатный ключ с [https://developers.giphy.com](https://developers.giphy.com) для вкладки GIF в чатах. Без ключа вкладка скрыта.
   * `CRON_SECRET` — секретная строка для защиты роута фоновой доставки запланированных сообщений `/api/cron/deliver-scheduled`.
   * `TURN_URL`, `TURN_USER`, `TURN_PASS` — опциональный TURN-сервер для WebRTC звонков. По умолчанию звонки работают через публичные STUN-серверы Google.

## Шаг D. Отключение подтверждения Email

> **КРИТИЧЕСКИ ВАЖНО:** Пользователи в Огоньке регистрируются просто по нику и паролю, им не нужно переходить по ссылкам из почты! Для этого отключи подтверждение email в Supabase:

1. В левом меню Supabase нажми на раздел **Authentication** (иконка двух силуэтов людей).
2. В выпадающем меню Authentication выбери **«Providers»**.
3. Нажми на строку **«Email»** (она развернётся).
4. Найди тумблер **«Confirm email»** (Подтверждать email) и **ВЫКЛЮЧИ его** (переведи в серый выключенный режим).
5. Внизу блока нажми кнопку **«Save»** (Сохранить).

## Шаг E. Получение бесплатного ключа Google Gemini API

1. Открой сайт: [https://aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)
2. Войди под своим Google-аккаунтом.
3. Нажми синюю кнопку **«Create API key»** (Создать ключ API).
4. Выбери любой проект и нажми **«Create API key in existing project»** (или New Project).
5. Скопируй полученный ключ (начинается на `AIzaSy...`).
6. В файле `.env.local` вставь его:
   ```env
   GEMINI_API_KEY=AIzaSyТВОЙ_СКОПИРОВАННЫЙ_КЛЮЧ
   ```
7. Сохрани файл.

## Шаг F. Создание Telegram-бота у @BotFather

1. Открой приложение Telegram на телефоне или компьютере.
2. В поиске найди официального бота **@BotFather** (с синей галочкой) и нажми **Start**.
3. Отправь команду:
   ```text
   /newbot
   ```
4. Бот спросит имя: напиши, например, `Огонёк Дневник`.
5. Бот спросит юзернейм (должен оканчиваться на `bot`): например, `MyOgonekDiaryBot`.
6. BotFather поздравит тебя и выдаст **HTTP API токен** (длинная строка вида `7123456789:AAHq_Abc123...`).
7. Скопируй этот токен и вставь в `.env.local`:
   ```env
   TELEGRAM_BOT_TOKEN=7123456789:AAHq_Abc123...твой_токен
   TELEGRAM_BOT_USERNAME=@MyOgonekDiaryBot
   ```
8. Сохрани файл.

## Шаг H. Деплой на Vercel (публичная ссылка для друзей)

1. Зарегистрируйся на [https://vercel.com](https://vercel.com) (лучше войти через GitHub).
2. Загрузи проект в свой репозиторий на GitHub (`git push`).
3. В панели Vercel нажми кнопку **«Add New...» → «Project»**.
4. Выбери свой репозиторий `ogonyok-ai-clone` и нажми **«Import»**.
5. В блоке **«Environment Variables»** добавь 5 переменных из твоего файла `.env.local`:
   * `NEXT_PUBLIC_SUPABASE_URL`
   * `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   * `SUPABASE_SERVICE_ROLE_KEY`
   * `GEMINI_API_KEY`
   * `TELEGRAM_BOT_TOKEN`
   * `TELEGRAM_BOT_USERNAME`
   * `CRON_SECRET`
6. Нажми кнопку **«Deploy»**.
7. Через 1–2 минуты Vercel выдаст тебе красивую публичную ссылку (например, `https://ogonyok-ai.vercel.app`), которую можно отправить друзьям!

## Шаг I. Настройка вебхука Telegram-бота

Чтобы бот мгновенно связывал аккаунт при нажатии Start:
1. Открой в браузере твой развёрнутый сайт:
   `https://твой-домен.vercel.app/api/telegram/setup` (методом POST) или перейди в приложении в **Настройки → Напоминания в Telegram**.
2. Либо выполни в терминале одну команду (замени адрес на свой):
   ```bash
   curl -X POST https://твой-домен.vercel.app/api/telegram/setup
   ```
3. Telegram ответит `{"ok": true, "result": true, "description": "Webhook was set"}`.
   * *Готово! Теперь бот автоматически связывает друзей при клике по ссылке.*

## Шаг J. «Если не работает» — 10 частых проблем

1. **При регистрации пишет «Database error saving user»:**
   * *Причина:* Не выключено подтверждение Email в Supabase.
   * *Решение:* Зайди в Supabase → Authentication → Providers → Email → выключи тумблер `Confirm email` и нажми Save (см. Шаг D).
2. **Пишет «Таблицы не найдены» или «relation profiles does not exist»:**
   * *Причина:* Забыл выполнить SQL-скрипт.
   * *Решение:* Открой `supabase/schema.sql`, скопируй всё и выполни в SQL Editor (см. Шаг B).
3. **Красная плашка или ошибка «Invalid API key»:**
   * *Причина:* Ошибка в ключе или пробел в конце строки в `.env.local`.
   * *Решение:* Проверь файл `.env.local` — убедись, что нет кавычек и лишних пробелов в конце ключей.
4. **Не работает ИИ («ИИ не подключён»):**
   * *Причина:* Не указан `GEMINI_API_KEY` в Vercel или в `.env.local`.
   * *Решение:* Получи бесплатный ключ на Google AI Studio (Шаг E) и добавь в переменные.
5. **Друг на телефоне открывает ссылку, но видит белый экран:**
   * *Причина:* Ошибка в переменной `NEXT_PUBLIC_SUPABASE_URL` в Vercel.
   * *Решение:* Переменные с префиксом `NEXT_PUBLIC_` должны быть добавлены в настройках проекта Vercel (Settings → Environment Variables) перед сборкой. После добавления нажми **Redeploy**.
6. **Бот в Telegram не присылает тестовое сообщение:**
   * *Причина:* Бот ещё не запущен пользователем.
   * *Решение:* Открой своего бота в Telegram и нажми кнопку **Start** (или напиши `/start`), чтобы бот получил право отправлять тебе сообщения.
7. **«Смена уровня заблокирована»: почему я не могу выбрать другой уровень?**
   * *Причина:* По Правилу 2 ТЗ менять уровень сложности можно не чаще 1 раза в 30 дней.
   * *Решение:* В Настройках показывается обратный отсчёт дней. Дождись окончания периода или измени дату в базе данных.
8. **Почему стрик не увеличился после записи?**
   * *Причина:* Стрик равен количеству *закрытых* дней. День закрывается только тогда, когда набрана норма гордостей И благодарностей по выбранному уровню.
   * *Решение:* Допиши нужное количество гордостей и благодарностей до дневной нормы, и день закроется.
9. **Записал второй день подряд за сегодня, а стрик не вырос:**
   * *Причина:* Защита от накликивания (Правило 5 ТЗ): максимум 1 новый день дневника закрывается за одни календарные сутки.
   * *Решение:* Все записи сохраняются в день, следующий день закроется завтра.
10. **Как перенести свои старые 700+ дней из браузера?**
    * *Решение:* Войди в свой аккаунт, открой Настройки — вверху появится баннер «Найдена история из локального дневника». Нажми кнопку **«Перенести в облако»**, и все дни загрузятся в твой аккаунт навсегда!
